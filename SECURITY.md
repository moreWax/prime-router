## Trust and data

The controller/author/reviewer roles are **prompt instructions, not permissions**. The reviewer is asked not to edit, but this package does not enforce read-only filesystem access or tool restrictions. For untrusted tasks, review/test in a protected worktree or separately restricted environment. Inspect child changes and command output before trusting a PASS report. Native admission and account authorization remain Prime Agent's responsibility.

Saved role defaults at `getAgentDir()/router/models.json` and branch-local session overrides include model selectors; treat local configuration and session data as potentially sensitive. Do not put credentials in model selectors. Malformed saved defaults are reported and not silently replaced; they block new session snapshots and saved-default writes, while valid existing session snapshots can continue. Saving defaults does not change existing sessions, and model settings do not grant account authorization or change the active parent model.

The workflow can write `.router/runs/<run-id>/state.json` and evidence logs. These may contain task text, file paths, code, test output, credentials, or other sensitive material. `.router/runs/` is ignored by this checkout's `.gitignore`, but ignore rules do not protect uploaded archives, shared disks, copied logs, or other projects. Keep artifacts local, restrict access, redact before sharing, and remove them when no longer needed. Do not include secrets in task prompts if avoidable.

No automatic publication, release, package upload, or external repository change occurs in this package. `/router <task>` preflight checks the live model catalog; it does not override admission. Continuation is agent-driven, not deterministic, so confirm status and evidence before relying on the result.

## Herdr bridge boundaries

Herdr display is opt-in. Normally run `/router herdr on` in your existing root session from its attached Herdr terminal; `/router herdr status`, `/router herdr sync`, and `/router herdr off` inspect, reconcile, and stop it. The updated Prime host's command-only `getInvokingClientContext()` supplies the **actual invoking client's** Herdr workspace/tab/pane/socket and current Prime daemon socket/launcher. Router must not substitute process environment when this capability or a Herdr invoking client is absent. Update Prime source runtime code, then use its supported lifecycle to restart the daemon **and affected session worker** and resume the same saved session. Restarting only the daemon may preserve an old worker; `/reload` does not add host support. Do not invent shutdown/resume commands, copy another session's IDs or socket, hand-edit caller context, switch to a different session, or share credentials to work around an error. No published release or version is promised; running processes are not upgraded by source edits. If an old inherited-context binding has no saved caller context, disable it from the original Herdr environment before enabling a one-command binding from a new client.

For advanced troubleshooting, explicit `/router herdr on <absolute-prime-daemon-socket> <absolute-prime-launcher>` still requires real inherited Herdr context and the exact current daemon. The packaged `bin/herdr-bind.mjs` and `/router herdr bind <absolute-descriptor-path>` remain a manual option in the exact same existing root. The descriptor has a 120-second lifetime, must be a private same-user file under a private directory, and is atomically claimed once then deleted even on failure; symlinks and wrong ownership or permissions are refused. A descriptor proves local same-user intent, **not cryptographic proof against a malicious same-user process**. Protect its path and branch-local metadata; do not pass either to untrusted users. Bare `on` never silently falls back to manual binding. The bridge checks direct children with the public Prime CLI list and attaches viewer panes to their existing native sessions; it does not grant model permissions or start extra agents. A pane may expose prompts, outputs, paths, command logs, and other sensitive context to viewers in that workspace. Herdr/Prime access controls, session IDs, and socket permissions still apply; a sidebar row or role label is not authorization.

The bound transport and pane ownership registry live in branch-local session metadata and can contain sensitive IDs and paths. Protect that session data. `/router herdr status` hides bound socket and launcher paths and arbitrary transport errors, but exposes caller pane ID and counts; do not paste private status or session data into public reports. Tracked viewer counts are **not** proof of current pane ownership.

For installed Herdr **0.9.1 / protocol 22**, the bridge requires a successful strict workspace-scoped `pane list` including the bound origin before treating a missing viewer as truly absent. Malformed inventories, wrong-workspace entries, missing origin, duplicate pane IDs, or CLI/server errors fail closed and retain ownership records. A proven-absent record can be dropped and recreated for an active child. A present pane can be closed only after exact workspace/tab/ID and `router_owner` token verification. A mismatched token or changed native child identity remains tracked for manual recovery, not adopted or force-closed. If split succeeds but metadata fails before the token is installed, an unverified orphan may remain; even `/router herdr off` does **not** authorize an unsafe close. Resolve such records through trusted, manual Herdr inspection; do not delete metadata or guess which pane is safe. Recheck this inventory contract against the installed server before upgrading Herdr.

The bridge does not kill native Prime children or erase sessions. Missing context or a failed list/attach reports an error. Unverified or ambiguous child metadata is not used to guess a binding; excess direct children beyond eight viewer slots are deferred. Role labels derive from unique exact model matches, so they are hints, not proof of a child's task. `working` requires explicit native `isStreaming` or `isCompacting` truth; otherwise activity is `unknown`, not a guarantee of idle or done. Event-driven snapshots may lag; use `sync` to request reconciliation and inspect Prime's native status before acting on an apparently stale pane. Separate Agents-sidebar registration is not verified by local tests; validate in a live Herdr session before trusting it.

## Report a vulnerability

For this public repository, first check its GitHub **Security** tab. If GitHub shows **Report a vulnerability**, use that private reporting form. If it does not, open a public issue that asks the maintainers to provide a private reporting route, but include no vulnerability details. Do not post secrets, session IDs, socket paths, reproduction details, or a working exploit publicly. The repository currently declares no security email or response-time promise, and reporting must not depend on private-repository membership. Once a private route is available, include the affected component, impact, and redacted reproduction steps; confirm that a maintainer received the report.
