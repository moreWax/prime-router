## Components and hooks

`package.json` registers `extensions/router.ts` and `skills/router/SKILL.md`. The extension reads the skill as workflow instructions. On ordinary turns and queued native child exit notices, `before_agent_start` appends those instructions to the existing system prompt **only** for the effective configured controller model; a marker prevents duplicate injection. Explicit child replies in the tested Prime behavior bypass that hook and reset the effective system prompt. The `context` hook supplies a transient, non-durable custom instruction message before the provider call when the controller prompt lacks the marker. It removes its own stale message after a model change. Neither hook creates a child, queues continuation, or changes the parent model. The built-in controller/author/reviewer selectors are `openai-codex/gpt-6-astra`, `openai-codex/gpt-5.6-sol`, and `openai-codex/gpt-5.6-luna`.

`/router <task>` is optional. Under a matching controller, it checks Prime's live executable-model catalog for **both** effective child selectors, reads the skill, then sends the task to the existing parent (as a follow-up if busy). It reports missing discovery/models without dispatch. Native spawn remains the final admission check.

## Role settings

`/router` shows status and offers an interactive role/model/scope picker in a UI (current-session override or saved default for new sessions); without a UI it shows status/help. `/router models` displays the effective settings without the picker. `/router model <controller|author|reviewer> <provider/model-id>` sets a current-session override. `/router default <role> <provider/model-id>` saves a default for new sessions only. `/router reset <role|all>` clears overrides back to this session's frozen defaults. Current-session changes require an idle session and apply to later turns, never rerouting in-flight work. Saved defaults can be changed while busy. Current-session overrides are stored as branch-local session metadata and survive reload/resume; changing saved defaults does not alter sessions already created. Precedence is current branch override, then frozen session default, then built-in selector at initial setup. Router does not migrate any saved or session value when built-ins change. Reset clears an override but still reveals the frozen session default, even if that value is stale; operators must use explicit current-session and future-default commands to update those scopes. The configured controller must match the *actual active model*; Router never changes the parent model for you. Native exact admission remains authoritative. Router fails closed without an explicit `rlmDepth === 0` root-session header. Native children (`rlmDepth > 0`) are disabled even if their model matches. Older or unknown-depth sessions may not support settings or automatic routing; do not edit session data to bypass this guard. Malformed saved defaults block new snapshots and saved-default writes; existing valid session snapshots can continue using their frozen settings and current-session controls. Router reports errors and does not silently repair the file.

## Opt-in Herdr bridge

Bare `/router herdr on` is the normal, default-off bridge setup for the existing **root session** when its command is invoked from a genuine Herdr client. The optional command-only host API `ctx.getInvokingClientContext?()` supplies `{env, daemonSocketPath, launcherPath}` from that actual attached command client; `env` holds its Herdr workspace/tab/pane and socket fields. The Prime host forwards this context across its supervisor/worker boundary for the invocation. Router does not derive it from stale worker process environment, infer a pane or daemon, switch sessions, or request credentials. Missing API or caller metadata fails with actionable incompatibility guidance. The API needs updated **source runtime code** in both daemon and session worker. A daemon restart alone may leave an old worker attached to the saved session: restart that worker through the supported lifecycle and resume the **same saved session**. `/reload` cannot install a host capability into either process. No exact released version is asserted; running processes are not upgraded by source edits. A legacy inherited-context binding without saved caller context must be turned off from its original Herdr environment before a new command-client binding is enabled.

Advanced troubleshooting retains `/router herdr on <absolute-prime-daemon-socket> <absolute-prime-launcher>` with genuine inherited Herdr context and the packaged `bin/herdr-bind.mjs` helper followed by `/router herdr bind <absolute-descriptor-path>` in the same existing root. Both require the exact live root/daemon and real Herdr caller; explicit command paths with spaces are unsupported. The private descriptor expires in 120 seconds, is atomically claimed once and deleted even after validation or sync failure, and rejects root mismatch, symlinks, or unsafe permissions. Bare `on` does not silently fall back to either path. `/router herdr off|status|sync` controls shutdown, state inspection, and manual reconciliation. `on` attempts initial reconciliation. The enabled flag, transport, caller context where applicable, and owned-pane registry persist in branch-local session metadata for reload/resume; an invalid ownership record is not trusted. The bridge does not change models, Prime child admission, or the parent session.

Reconciliation first checks that the public Prime CLI list on the selected daemon includes this same live top-level parent session. It then obtains native **direct** children from that list, not by parsing prompts or starting a second agent. At most eight live direct-child viewer panes are supported. Each eligible child gets a no-focus sibling Herdr pane whose viewer runs `prime-agent attach <exact child sessionId> --daemon-socket <exact supplied socket>` through the selected launcher. The attach views that *same* native session and does not create another model agent. Child name and model come from native metadata. The author or reviewer role is inferred only from a unique exact model match to effective configured selectors; otherwise the label is `worker`. The mapping cannot prove a child's actual prompt role.

Supported parent `tool_execution_end` and `agent_end` events schedule coalesced snapshot reconciliation, with no polling. Child-only terminal transitions can remain stale until a later parent event or explicit `sync`. The bridge reports the viewer agent state as `unknown`, not as a verified working/idle/done state. These snapshots are not real-time lifecycle guarantees. The goal is **one entry per native child in Herdr's Agents sidebar**. Pane creation and reported pane metadata do not establish that Herdr registered or recognized such rows; only a later live Herdr test can verify this. A dashboard fallback is not the target. See [Getting started](GETTING_STARTED.md) and [Security](SECURITY.md).

## Agent-driven run

1. The controller defines acceptance criteria, checks existing edits, and records a compact checkpoint at `.router/runs/<run-id>/state.json` unless local artifacts are forbidden.
2. The controller admits the **effective author model** via native `rlm.spawn` as code author. A spawn return means admission, not completion. Independent nonoverlapping author scopes can run in parallel.
3. After inspecting the author's reply and actual diff, the controller admits the **effective reviewer model** via native `rlm.spawn` as review/test runner. The reviewer is instructed not to edit and must report commands, exit codes, findings, and missing checks.
4. The controller verifies evidence, asks the author to fix confirmed defects, and repeats review at most **three author→reviewer rounds per step by default**. It stops for an operator if a blocker or cap persists, rather than auto-looping.

The checkpoint tracks phase, step, scopes, child IDs, review count, evidence, and unresolved findings; the actual working tree must be reconciled on resumption. On a native child reply or `[child-exited: ...]` notice, the controller recovers handles with `rlm.list_subagents()`, may use nonblocking `rlm.collect(..., timeout_ms=0)` or bounded observation, and performs the next useful action. A no-reply exit is not success: missing reports receive at most **two** native recovery attempts before reporting a blocker. It does not busy-poll or schedule blind follow-ups.

Prime owns provider calls, the inner agent loop, and native follow-up delivery. Prompt instructions guide the controller's choices but do not guarantee that it will continue if a follow-up is paused, lost, or ignored. Native children remain visible in the current session's agent tree; there is no shadow session, subprocess agent, or parent replacement. Role prompts are not enforcement boundaries; see [Security](SECURITY.md).
